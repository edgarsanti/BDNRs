Neo4j: primeros comandos y consultas con Cypher

Práctica de creación, consultas y recorridos de grafos

1 ¿Qué es Cypher?

Cypher es el lenguaje utilizado para crear y consultar información en Neo4j. Permite escribir patrones que representan nodos, relaciones y propiedades.

En esta práctica aprenderemos a crear una pequeña red social, consultar sus conexiones y recorrer caminos entre personas.

Utilizaremos variables descriptivas como origen, destino, intermedio y relacion, para identificar claramente cada elemento.

1.1 ¿Cómo se representan los nodos y las relaciones?

Observemos el siguiente patrón:

(origen:Persona)-[:CONOCE]->(destino:Persona)

Este patrón representa dos nodos conectados mediante una relación dirigida.

  • (origen:Persona): nodo donde comienza la relación.
  • [:CONOCE]: tipo de relación entre los nodos.
  • ->: dirección de la relación.
  • (destino:Persona): nodo donde termina la relación.

También podemos representar un nodo con propiedades:

(persona:Persona {nombre: 'Ana'})

En este ejemplo:

  • persona es una variable temporal.
  • Persona es la etiqueta del nodo.
  • nombre es una propiedad.
  • 'Ana' es el valor almacenado.

1.2 Elementos básicos de Cypher

Elemento Función
() Representar nodos
[] Representar relaciones
-> Indicar dirección
:Persona Etiqueta del nodo
:CONOCE Tipo de relación
{nombre: 'Ana'} Propiedad y valor
MATCH Buscar patrones existentes
CREATE Crear nodos o relaciones
WHERE Filtrar resultados
RETURN Mostrar información
DELETE Eliminar elementos seleccionados
DETACH DELETE Eliminar nodos y sus relaciones
ImportanteVariables, etiquetas y propiedades

En el patrón (origen:Persona), origen es una variable temporal y Persona es una etiqueta.

Podemos utilizar variables como origen, usuario o persona1 sin modificar la información almacenada.

Las variables no son los nombres permanentes de los nodos.

1.3 Consultas en Neo4j

En las siguientes secciones, las consultas Cypher aparecerán en recuadros de código con un botón para copiarlas y ejecutarlas en Neo4j Query.

Aunque utilizamos el resaltado visual de SQL para mostrar correctamente ese botón en Quarto, el lenguaje de las consultas es Cypher.

Los ejemplos de nodos, relaciones y caminos se presentarán como texto explicativo.

2 Preparar una base limpia antes de la práctica

Antes de comenzar, comprobaremos si existen nodos y relaciones de ejercicios anteriores.

Esto es importante porque ejecutar varias veces CREATE puede generar elementos duplicados.

2.1 Consultar el número de nodos

Ejecutamos:

MATCH (n)
RETURN COUNT(n) AS TotalNodos;

Explicación línea por línea

  • Línea 1: MATCH (n) busca todos los nodos existentes.
  • Línea 2: COUNT(n) cuenta los nodos y AS TotalNodos establece el nombre de la columna.

Resultado esperado: se mostrará la cantidad de nodos almacenados.

2.2 Consultar el número de relaciones

Ejecutamos:

MATCH ()-[relacion]->()
RETURN COUNT(relacion) AS TotalRelaciones;

Explicación línea por línea

  • Línea 1: busca relaciones de cualquier tipo entre nodos.
  • Línea 2: cuenta las relaciones encontradas.

Resultado esperado: se mostrará el número de relaciones almacenadas.

2.3 Eliminar los datos anteriores

AdvertenciaAdvertencia

La siguiente consulta elimina permanentemente todos los nodos y relaciones de la base de datos seleccionada.

Únicamente debe utilizarse en una base destinada a esta práctica, cuando estemos seguros de que no contiene información que necesitamos conservar.

No elimina la instancia ni los índices y restricciones existentes.

Ejecutamos:

MATCH (n)
DETACH DELETE n;

Explicación línea por línea

  • Línea 1: identifica todos los nodos.
  • Línea 2: elimina esos nodos y sus relaciones conectadas.

Resultado esperado: se eliminan los nodos y las relaciones de la base seleccionada.

2.4 Comprobar que la base quedó vacía

Consultamos los nodos:

MATCH (n)
RETURN COUNT(n) AS TotalNodos;

Resultado esperado: 0 nodos.

Consultamos las relaciones:

MATCH ()-[relacion]->()
RETURN COUNT(relacion) AS TotalRelaciones;

Resultado esperado: 0 relaciones.

3 Crear nuestro primer nodo: Ana

Comenzaremos creando una persona llamada Ana.

Ejecutamos:

CREATE (persona:Persona {nombre: 'Ana'})
RETURN persona;

Explicación línea por línea

  • Línea 1: crea un nodo con etiqueta Persona y propiedad nombre = 'Ana'. La variable persona representa temporalmente el nodo.
  • Línea 2: devuelve el nodo creado.

Resultado esperado: un nodo llamado Ana y ninguna relación.

4 Crear un segundo nodo: Carlos

Ahora crearemos una segunda persona.

Ejecutamos:

CREATE (persona:Persona {nombre: 'Carlos'})
RETURN persona;

Explicación línea por línea

  • Línea 1: crea un nodo llamado Carlos.
  • Línea 2: devuelve el nodo.

Resultado esperado: dos nodos y ninguna relación.

Nota¿Por qué reutilizamos la variable persona?

La variable persona solamente existe durante la ejecución de su consulta.

Por eso podemos utilizar ese mismo nombre en diferentes consultas sin modificar los nodos creados anteriormente.

5 Crear nuestra primera relación

Indicaremos que Ana conoce a Carlos.

La conexión que queremos representar es:

Ana → Carlos

Ejecutamos:

MATCH (origen:Persona {nombre: 'Ana'})
MATCH (destino:Persona {nombre: 'Carlos'})
CREATE (origen)-[:CONOCE]->(destino)
RETURN origen, destino;

Explicación línea por línea

  • Línea 1: busca a Ana y la representa mediante origen.
  • Línea 2: busca a Carlos y lo representa mediante destino.
  • Línea 3: crea una relación dirigida CONOCE desde Ana hacia Carlos.
  • Línea 4: devuelve ambos nodos.

Resultado esperado: dos nodos y una relación Ana → Carlos.

5.1 Consultar la relación creada

Ahora recuperaremos la relación almacenada.

Ejecutamos:

MATCH (origen:Persona)-[relacion:CONOCE]->(destino:Persona)
RETURN origen, relacion, destino;

Explicación línea por línea

  • Línea 1: busca relaciones de tipo CONOCE entre personas.
  • Línea 2: devuelve los nodos y la relación para mostrarlos en Graph.

Resultado esperado: visualizar la relación Ana → Carlos.

6 Agregar tres personas

Ahora agregaremos María, Luis y Sofía.

Ejecutamos:

CREATE (maria:Persona {nombre: 'María'})
CREATE (luis:Persona {nombre: 'Luis'})
CREATE (sofia:Persona {nombre: 'Sofía'})
RETURN maria, luis, sofia;

Explicación línea por línea

  • Línea 1: crea el nodo de María.
  • Línea 2: crea el nodo de Luis.
  • Línea 3: crea el nodo de Sofía.
  • Línea 4: devuelve los tres nodos.

Resultado esperado: cinco nodos y una relación.

7 Completar nuestra red social

Crearemos las conexiones restantes para construir una red de cinco personas.

Las relaciones que queremos representar son:

Origen Relación Destino
Ana CONOCE Carlos
Ana CONOCE María
Carlos CONOCE Luis
María CONOCE Luis
Sofía CONOCE María

La relación Ana → Carlos ya existe, por lo que solamente crearemos las otras cuatro.

Ejecutamos una sola vez:

MATCH (ana:Persona {nombre: 'Ana'})
MATCH (carlos:Persona {nombre: 'Carlos'})
MATCH (maria:Persona {nombre: 'María'})
MATCH (luis:Persona {nombre: 'Luis'})
MATCH (sofia:Persona {nombre: 'Sofía'})
CREATE (ana)-[:CONOCE]->(maria)
CREATE (carlos)-[:CONOCE]->(luis)
CREATE (maria)-[:CONOCE]->(luis)
CREATE (sofia)-[:CONOCE]->(maria)
RETURN ana, carlos, maria, luis, sofia;

Explicación línea por línea

  • Líneas 1 a 5: buscan los cinco nodos existentes.
  • Línea 6: conecta Ana → María.
  • Línea 7: conecta Carlos → Luis.
  • Línea 8: conecta María → Luis.
  • Línea 9: conecta Sofía → María.
  • Línea 10: devuelve los cinco nodos.

Resultado esperado: cinco nodos y cinco relaciones.

AdvertenciaEvitar duplicaciones

No debemos ejecutar repetidamente los comandos CREATE si ya generamos los elementos correspondientes.

De hacerlo, podemos crear nodos o relaciones duplicados y obtener resultados diferentes a los esperados.

7.1 Visualizar el grafo completo

Ejecutamos:

MATCH (origen:Persona)-[relacion:CONOCE]->(destino:Persona)
RETURN origen, relacion, destino;

Explicación línea por línea

  • Línea 1: busca todas las conexiones CONOCE.
  • Línea 2: devuelve los nodos y relaciones.

Resultado esperado: la red completa de cinco personas y cinco relaciones.

8 Eliminar nodos y relaciones específicas

Hasta ahora hemos aprendido a crear nodos y relaciones en Neo4j.

Sin embargo, también podemos eliminar elementos específicos sin borrar toda la base de datos.

Existen dos operaciones importantes:

  • Eliminar una relación: desaparece la conexión, pero los nodos permanecen.
  • Eliminar un nodo: desaparece el nodo seleccionado. Si tiene relaciones, podemos utilizar DETACH DELETE para eliminarlas también.

8.1 Eliminar una relación específica

Supongamos que queremos eliminar únicamente la relación entre Ana y Carlos.

Ana → Carlos

Primero verificamos que la relación exista.

Ejecutamos:

MATCH (origen:Persona {nombre: 'Ana'})
      -[relacion:CONOCE]->
      (destino:Persona {nombre: 'Carlos'})
RETURN origen, relacion, destino;

Explicación línea por línea

  • Línea 1: busca el nodo llamado Ana.
  • Línea 2: busca una relación dirigida de tipo CONOCE y la representa mediante relacion.
  • Línea 3: establece que el destino debe ser Carlos.
  • Línea 4: devuelve los elementos encontrados.

Resultado esperado: la relación Ana → Carlos.

8.2 Eliminar la relación

Ahora eliminaremos esa conexión.

Ejecutamos:

MATCH (origen:Persona {nombre: 'Ana'})
      -[relacion:CONOCE]->
      (destino:Persona {nombre: 'Carlos'})
DELETE relacion;

Explicación línea por línea

  • Línea 1: localiza a Ana como origen.
  • Línea 2: busca la relación dirigida CONOCE.
  • Línea 3: exige que Carlos sea el destino.
  • Línea 4: DELETE relacion elimina la relación encontrada.

Resultado esperado: desaparece la conexión Ana → Carlos, pero ambos nodos permanecen almacenados.

Nota¿Qué ocurre con los nodos?

Al utilizar DELETE relacion, solamente eliminamos las conexiones seleccionadas.

Los nodos de origen y destino siguen existiendo.

Si hubiera varias relaciones que cumplieran el patrón, se eliminarían todas esas coincidencias.

8.3 Comprobar la eliminación de la relación

Ejecutamos:

MATCH (origen:Persona {nombre: 'Ana'})
      -[relacion:CONOCE]->
      (destino:Persona {nombre: 'Carlos'})
RETURN origen, relacion, destino;

Explicación línea por línea

  • Líneas 1 a 3: buscan nuevamente la relación Ana → Carlos.
  • Línea 4: devuelve las coincidencias, si existen.

Resultado esperado: ninguna relación encontrada.

8.4 Crear nuevamente la relación eliminada

Para continuar con nuestra práctica, recuperaremos la conexión entre Ana y Carlos.

Ejecutamos:

MATCH (origen:Persona {nombre: 'Ana'})
MATCH (destino:Persona {nombre: 'Carlos'})
CREATE (origen)-[:CONOCE]->(destino)
RETURN origen, destino;

Explicación línea por línea

  • Línea 1: busca a Ana.
  • Línea 2: busca a Carlos.
  • Línea 3: crea nuevamente la relación Ana → Carlos.
  • Línea 4: devuelve los nodos involucrados.

Resultado esperado: volvemos a tener cinco nodos y cinco relaciones.

9 Eliminar un nodo específico

Ahora supongamos que queremos eliminar a Sofía.

Actualmente existe la conexión:

Sofía → María

Primero consultaremos el nodo de Sofía.

Ejecutamos:

MATCH (persona:Persona {nombre: 'Sofía'})
RETURN persona;

Explicación línea por línea

  • Línea 1: busca un nodo con etiqueta Persona y nombre Sofía.
  • Línea 2: devuelve el nodo encontrado.

Resultado esperado: un nodo llamado Sofía.

9.1 Eliminar el nodo y sus relaciones

Ejecutamos:

MATCH (persona:Persona {nombre: 'Sofía'})
DETACH DELETE persona;

Explicación línea por línea

  • Línea 1: busca el nodo de Sofía.
  • Línea 2: elimina ese nodo y todas sus relaciones conectadas.

Resultado esperado: Sofía desaparece del grafo junto con su relación hacia María.

Nuestra red tendrá ahora:

  • Cuatro nodos.
  • Cuatro relaciones.
AdvertenciaDiferencia entre DELETE y DETACH DELETE

DELETE persona permite eliminar un nodo solamente si no tiene relaciones conectadas.

Si el nodo tiene relaciones, debemos eliminarlas primero o utilizar DETACH DELETE persona.

DETACH DELETE elimina el nodo junto con sus relaciones.

Si hubiera varios nodos con el nombre Sofía, esta consulta eliminaría todos los que cumplieran la condición.

9.2 Comprobar que Sofía se eliminó

Ejecutamos:

MATCH (persona:Persona {nombre: 'Sofía'})
RETURN persona;

Explicación línea por línea

  • Línea 1: busca nuevamente a Sofía.
  • Línea 2: devuelve el nodo si todavía existe.

Resultado esperado: ninguna coincidencia.

9.3 Crear nuevamente el nodo de Sofía

Para recuperar nuestra red original, primero crearemos nuevamente el nodo.

Ejecutamos:

CREATE (persona:Persona {nombre: 'Sofía'})
RETURN persona;

Explicación línea por línea

  • Línea 1: crea nuevamente el nodo Sofía.
  • Línea 2: devuelve el nodo creado.

Resultado esperado: cinco nodos y cuatro relaciones.

9.4 Recuperar la relación Sofía → María

Ahora crearemos la conexión que tenía Sofía antes de eliminarla.

Ejecutamos:

MATCH (origen:Persona {nombre: 'Sofía'})
MATCH (destino:Persona {nombre: 'María'})
CREATE (origen)-[:CONOCE]->(destino)
RETURN origen, destino;

Explicación línea por línea

  • Línea 1: busca a Sofía.
  • Línea 2: busca a María.
  • Línea 3: crea la relación dirigida desde Sofía hacia María.
  • Línea 4: devuelve los nodos involucrados.

Resultado esperado: nuevamente tendremos cinco nodos y cinco relaciones.

10.1 Resumen de los comandos de eliminación

Comando Función
DELETE relacion Elimina una relación seleccionada.
DELETE persona Elimina un nodo sin relaciones conectadas.
DETACH DELETE persona Elimina el nodo y sus relaciones.
MATCH (n) DETACH DELETE n Elimina todos los nodos y relaciones de la base seleccionada.
TipPara recordar

Antes de eliminar elementos, podemos ejecutar una consulta con MATCH y RETURN para comprobar qué nodos o relaciones serán afectados.

Después de utilizar DELETE o DETACH DELETE, podemos repetir la consulta para verificar que la eliminación se realizó correctamente.

Los ejemplos de esta sección recuperan la red original para que podamos continuar con las consultas siguientes.

11 ¿A quién conoce Ana?

Ahora que tenemos la red completa, comenzaremos a consultar las relaciones directas.

Queremos responder:

¿Qué personas conoce Ana?

Ejecutamos:

MATCH (origen:Persona)-[:CONOCE]->(destino:Persona)
WHERE origen.nombre = 'Ana'
RETURN destino.nombre AS Persona;

Explicación línea por línea

  • Línea 1: busca relaciones dirigidas CONOCE entre dos personas.
  • Línea 2: establece que el nodo de origen debe tener el nombre Ana.
  • Línea 3: devuelve el nombre de cada destino.

Resultado esperado:

Persona
Carlos
María

El orden de las filas no está garantizado si no utilizamos ORDER BY.

11.1 ¿Qué representan las variables?

En esta consulta, origen y destino son variables temporales.

Neo4j encuentra dos coincidencias:

Origen Destino
Ana Carlos
Ana María

La variable destino representa a Carlos en la primera coincidencia y a María en la segunda.

Las variables nos ayudan a identificar los nodos durante la ejecución de cada consulta.

11.2 Visualizar las conexiones directas de Ana

Ejecutamos:

MATCH (origen:Persona)-[relacion:CONOCE]->(destino:Persona)
WHERE origen.nombre = 'Ana'
RETURN origen, relacion, destino;

Explicación línea por línea

  • Línea 1: busca las relaciones CONOCE y las asigna temporalmente a relacion.
  • Línea 2: selecciona las relaciones que salen de Ana.
  • Línea 3: devuelve los nodos y sus conexiones.

Resultado esperado: visualizar Ana → Carlos y Ana → María.

13 Buscar relaciones sin exigir dirección

Las relaciones almacenadas en Neo4j tienen dirección.

Sin embargo, podemos buscar conexiones sin importar el sentido de la flecha.

Ejecutamos:

MATCH (maria:Persona {nombre: 'María'})-[:CONOCE]-(persona:Persona)
RETURN DISTINCT persona.nombre AS Persona;

Explicación línea por línea

  • Línea 1: busca personas conectadas con María mediante CONOCE, sin exigir una dirección.
  • Línea 2: devuelve los nombres encontrados sin repeticiones.

Resultado esperado:

Persona
Ana
Luis
Sofía
NotaDirección de las relaciones

Una consulta sin flecha no modifica la dirección de las relaciones almacenadas.

Solamente permite encontrar coincidencias en cualquiera de los dos sentidos.

14 Relaciones directas e indirectas

Una relación directa conecta dos nodos mediante una sola relación.

Por ejemplo:

Ana → Carlos

Una conexión indirecta utiliza dos o más relaciones.

Por ejemplo:

Ana → Carlos → Luis

Ana → María → Luis

Por lo tanto, Ana está conectada indirectamente con Luis mediante dos personas diferentes.

Nota¿Neo4j encuentra automáticamente las conexiones?

Neo4j puede recorrer las relaciones almacenadas para encontrar caminos entre los nodos.

Nosotros debemos indicar el patrón que queremos buscar mediante Cypher.

Neo4j no crea automáticamente una relación nueva entre Ana y Luis.

15 Buscar todas las conexiones a dos pasos desde Ana

Queremos responder:

¿A qué personas puede llegar Ana después de recorrer dos relaciones CONOCE?

Ejecutamos:

32 Ideas clave

  • Cypher permite trabajar con nodos y relaciones mediante patrones.
  • Las variables representan temporalmente los elementos encontrados.
  • Las etiquetas permiten clasificar los nodos.
  • Las propiedades almacenan información.
  • CREATE agrega nodos o relaciones.
  • MATCH busca patrones existentes.
  • WHERE permite establecer condiciones.
  • RETURN determina qué información mostramos.
  • DELETE elimina elementos seleccionados.
  • DETACH DELETE permite eliminar nodos y sus relaciones.
  • Las relaciones tienen dirección, aunque podemos consultarlas sin exigirla.
  • Los caminos indirectos utilizan varias relaciones existentes.
  • DISTINCT elimina resultados repetidos.
  • length() devuelve la cantidad de relaciones de un camino.
  • COUNT() permite contar coincidencias.
  • ORDER BY permite ordenar resultados.
  • LIMIT restringe la cantidad de filas mostradas.
  • Las recomendaciones requieren definir criterios de búsqueda mediante consultas.

34.6 Calcular la distancia total de cada recorrido

MATCH camino = (origen:Ciudad {nombre: 'Xalapa'})
               -[:RUTA*1..4]->
               (destino:Ciudad {nombre: 'Ciudad de México'})
RETURN [n IN nodes(camino) | n.nombre] AS Recorrido,
       reduce(total = 0, r IN relationships(camino) |
              total + r.distancia_km) AS DistanciaTotal
ORDER BY DistanciaTotal;

Resultado esperado: una tabla con los recorridos y su distancia total acumulada.

Por ejemplo:

Recorrido DistanciaTotal
Xalapa → Puebla → Ciudad de México 310
Xalapa → Pachuca → Ciudad de México 330
Xalapa → Tlaxcala → Pachuca → Ciudad de México 390

La función nodes(camino) obtiene los nodos que forman el recorrido.

La función relationships(camino) obtiene sus relaciones.

Finalmente, reduce() suma las distancias de cada relación para obtener la distancia total.

34.7 Comparar distancia, tiempo y costo de las rutas

MATCH camino = (origen:Ciudad {nombre: 'Xalapa'})
               -[:RUTA*1..4]->
               (destino:Ciudad {nombre: 'Ciudad de México'})
RETURN [n IN nodes(camino) | n.nombre] AS Recorrido,
       reduce(d = 0, r IN relationships(camino) |
              d + r.distancia_km) AS DistanciaKM,
       reduce(t = 0, r IN relationships(camino) |
              t + r.tiempo_min) AS TiempoMin,
       reduce(c = 0, r IN relationships(camino) |
              c + r.costo) AS CostoMXN
ORDER BY CostoMXN;

No demuestra que todos los sistemas dejarían de funcionar, sino que identifica posibles dependencias que deberían revisarse.

36.10 Visualizar las conexiones de un dispositivo crítico

MATCH camino = (firewall:Firewall {id: 'FW-PRINCIPAL'})

               (dispositivo:ActivoTI)

Resultado esperado: una visualización de las conexiones del firewall principal, incluyendo dispositivos alcanzables mediante una o dos relaciones CONECTADO_A, sin importar su dirección.

Selecciona la vista Graph de Neo4j para observar los recorridos.

La expresión *1..2 permite explorar conexiones de uno o dos saltos.
